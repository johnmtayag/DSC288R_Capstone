## N3_Run_Model

This .py file contains the code necessary to run our models. Jupyter Notebooks do not have an easy way to utilize the GPU to parallelize data loading, so this is a .py file that is intended to be run locally.

Before running this code, ensure that all variables between ```Set variables``` and ```Model``` are correct. The main variables are listed here:

* <b>path</b>: This is the path leading to the src folder. This must be set in order for this file to work.
* <b>model_params</b>: This variable selects a set of model parameters for a specific model configuration
* <b>using_preprocessed_images</b>: This lets the model know whether to expect preprocessed images to be available in data/preprocessed_data/, or if it needs to perform image processing steps within the data loader
	* Set this to True if N1_1_EnvironmentSetup_TrainingAndTesting.ipynb was run. This is the recommended option
	* Set this to False if N1_2_EnvironementSetup_Testing.ipynb was run. This will take a lot longer to run due to computational overhead requirements
* <b>Main controls</b>
	* <b>train_model</b>: If True, train a new model using the parameters saved in model_params
		* All label datasets should be accessible from the associated filepath listed  if the environment setup notebooks were run. They are also available within the github repo.
	* <b>test_model</b>: If True, generate results for the test data
	* <b>validate_rad_model</b>: If True, generate results for the radiologist-labeled validation set
	* <b>test_rad_model</b>: If True, generate results for the radiologist-labeled test set.
* <b>Model Parameters</b>: These contain the batch sizes for the data loaders, fraction variables to only load some fraction of the image labels (used for testing purposes), and file paths leading to the label data frames.
* <b>use_cuda</b>: If True, use the GPU
* <b>n_workers</b>: Set this to the number of GPUs * 4 to parallelize the image loading process.

Once all parameters are set, run the code - the results will be deposited in a couple of places:

* The trained model will be saved as a .pth file in the models/ folder
* The generated data frame with predictions will be saved in the results/ folder
	* This will have the following filename structure:
	* {Model Configuration}\_{Test dataset type}\_withPredictionsAndConfidences.csv
* Losses will be saved to results/model_losses
* Training times will be saved to results/model_training_times
* Confusion matrices will be saved to resutls/confusion_matrix_images

## N6_GradCAM_Analysis

This notebook generates a set of metrics to evaluate correlations and similarities between Grad-CAM heat maps generated for each condition of a CXR. The pseudo-code for this is as follows:

1. For each model configuration:
	1. First all environmental variables are set up. This includes Grad-CAM variables, image processing pipeline variables, and the hilbert curve index.
	2. A sample of ```pca_sample_size``` row indexes are generated from the test dataset
		1. All images from the sample are opened, processed, and saved to a tensor
	3. For each sampled image:
		2. Extract the Grad-CAM mask for each condition (5 total)
		3. For each Grad-CAM mask:
			1. Resize the mask to the nearest power of 2 (round down) --> This is the hilbert_dim
			2. Unroll the mask into a 1D vector using the hilbert curve index to better preserve spatial relationships
		4. Save each Grad-CAM mask as a combined matrix of size (5, hilbert_dim^2)
		5. Apply a PCA transformation to reduce the size of the combined matrix to (5, 4), four components per mask
		6. Calculate specific metrics and add them to the running averages

The aggregated metrics are then saved as ```PCA_analysis_dicts.json``` to the ```results/gradcam/``` folder. This has the following structure:
